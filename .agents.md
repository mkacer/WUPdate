# Agent Instructions (WUPdate)

This file is a shared baseline for CLI coding agents working in this repository
(GitHub Copilot CLI, Claude Code, and similar tools).

## Project summary

- Project: **WUPdate**
- Language: **C++23**
- Platform: **Windows (Windows 11 / modern Windows Server)**
- Goal: native Windows Update CLI using WUA COM APIs
- No PowerShell runtime dependency
- No .NET dependency
- No ATL / MFC

## Build environment

Use a Visual Studio developer shell with Windows SDK environment loaded.

Required tools:

- Visual Studio Build Tools (MSVC)
- Windows SDK
- CMake
- Ninja

Build commands:

```powershell
cmake -S . -B build -G "Ninja"
cmake --build build --config Release
```

If switching toolchains or hitting cache/compiler mismatches, delete `build/`
and reconfigure.

## Coding standards

- Use `set(CMAKE_CXX_STANDARD 23)`.
- Prefer RAII and standard library facilities.
- No naked `new`/`delete`.
- Keep COM-facing strings as `std::wstring`; convert to UTF-8 at output boundaries.
- Use `Microsoft::WRL::ComPtr` for COM object lifetimes.
- Keep headers and implementation files separated.
- Avoid global mutable state.
- Keep warnings clean under `/W4` where practical.

## WUA/Windows behavior constraints

- Use WUA COM APIs directly (`wuapi.h` interfaces).
- Do not shell out to PowerShell for update operations.
- Settings changes under HKLM and service restarts require admin elevation.
- For settings reset operations, require explicit confirmation flags in CLI.

## CLI behavior expectations

- Commands should be deterministic and scriptable by default.
- Interactive actions must be opt-in via explicit flags (for example `--interactive`).
- `--verbose` should emit clear progress markers for long-running operations.
- WUPdate install should interactively prompt for each update and confirm intallation intent, unless --all is passed

## Testing and validation

- Prefer targeted builds/tests first.
- Do not introduce new build systems or external tooling unless needed.
- Validate changes compile with MSVC + Ninja in a developer shell.

## Safety rails for agents

- Do not run destructive cleanup commands outside repo scope.
- Do not delete policy keys or restart services without explicit user intent.
- Surface errors instead of silently ignoring failures.
- Keep edits focused; avoid unrelated refactors.

## Agent-specific notes

### GitHub Copilot CLI

- Prefer small, surgical patches.
- Prefer repository-native tools and existing conventions.
- Keep terminal output concise and actionable.

### Claude Code (or other CLI LLMs)

- Follow the same build/test commands and coding constraints above.
- Respect Windows-specific pathing and admin requirements.
- Do not replace WUA COM usage with wrappers/frameworks without user approval.
